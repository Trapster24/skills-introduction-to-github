## Reference: Claude model and feature pricing (official, platform.claude.com, fetched 2026-10-24)

### Takeaway
Current-generation Claude pricing is Opus 5.5 $4/$20, Sonnet 5.5 $2/$10, Haiku 5.5 $0.10/$0.50 per million input/output tokens; Fable 5.1 is $10/$50. ### Inferences
- For unattended agents, Sonnet 5.5 is the natural default: half the Opus 5.5 price with the same 1M context, and its cache-read rate ($0.10/MTok) makes long tool loops cheap once the prefix is stable. Haiku 5.5 at $0.10/$0.50 makes per-record jobs (enrichment, extraction, classification) nearly free; the per-record cost is then dominated by web search ($0.01 per search) rather than tokens.
- Batch (50%) plus caching is the largest "free" cost lever for anything no one is waiting on (overnight enrichment, backfills, evals). It cannot be used inside Managed Agents sessions.

## Key question 1: Minimum robust stack for unattended, revenue-generating agents with hard spend caps, and monthly cost

### Takeaway
A solo operator can run a defensible unattended stack for roughly £60–£150/month in fixed tooling plus capped model spend: Anthropic API key in a dedicated Console workspace with a monthly spend limit (and prepaid credits with auto-reload off as the backstop), Managed Agents scheduled deployments with a per-run dollar budget (or the Agent SDK on a ~€20 VPS), Langfuse (free hobby tier or $29 Core) for traces, n8n self-hosted (free) or Starter (~€24) for glue, Stripe for billing, and Attio free tier for CRM.

### Cited Findings

**Spend caps available from Anthropic (official)**
- Console workspaces: "Click on the 'Limits' tab. Choose 'Change Limit' to set a specific spend limit for this Workspace"; you can only set a limit lower than the organization's limit; unset workspaces inherit the org limit; you can add an email notification at a chosen dollar amount; "You can't set a spend limit for the Default Workspace" — [Anthropic support: Creating and managing workspaces](https://support.claude.com/en/articles/9796807-creating-and-managing-workspaces-in-the-claude-console) (fetched 2026-10-24)
- Setting org and workspace limits via the Admin API (`POST /v1/organizations/spend_limits`, amounts in cents) is "in an early access preview" — [search summary citing platform.claude.com Admin API docs](https://platform.claude.com/docs/de/api/go/beta/organization/spend_limits/set.md)
- The separate "Spend Limits API" (per-member limits, monthly period resetting 00:00 UTC on the 1st) "is available to Claude Enterprise organizations only. It is not available to Claude Platform (Claude Console) organizations" — [Spend Limits API](https://platform.claude.com/docs/en/manage-claude/spend-limits-api) (fetched 2026-10-24)
- Prepaid credits are the default billing model: "if you run out, you can no longer call the API or use the playground until you add more"; auto-reload is optional (threshold + target balance) — [Anthropic support: spend/billing article](https://support.claude.com/en/articles/8977456-how-do-i-set-up-and-manage-my-spend-limits) (fetched 2026-10-24)
- Behaviour when a user-set Console limit is hit is reported by a 3P source as HTTP 400 (tier cap as HTTP 429 until the 1st of next month) — [digitalapplied.com](https://www.digitalapplied.com/blog/ai-spend-controls-compared-usage-caps-2026) — NOT confirmed against Anthropic's own docs this session.
- Managed Agents session budgets: "a hard ceiling on the session's list cost"; `budget: {type: "limit", max_list_cost: {amount: "<cents>", currency: "USD"}}`; list cost counts "Model tokens, at each served model's list price; Web searches, at $10 USD per 1,000 searches; Session running time, at $0.08 USD per hour"; enforced between model requests so the final cost can land "a fraction past the cap" (e.g. a 50-cent cap pausing at 53 cents); session goes idle with `stop_reason: budget_reached`, is not terminated, and only settle events are accepted until the budget is raised or removed; a budget can only be attached at creation; removal is one-way — [Managed Agents: Session budgets](https://platform.claude.com/docs/en/managed-agents/budgets) (fetched 2026-10-24)
- Scheduled deployments: cron expression + IANA timezone, minute granularity; each firing creates a new session; the deployment's `budget` "is copied onto each session it starts, so the budget bounds every run separately" ("a deployment with a '2000' cap can spend up to about $20 USD on every run"); pause/unpause/archive; failed runs are recorded with error types; unrecoverable errors auto-pause the deployment; up to 1,000 deployments per org; jitter up to 15% of the interval (max 9 minutes) — [Managed Agents: Scheduled deployments](https://platform.claude.com/docs/en/managed-agents/scheduled-deployments) (fetched 2026-10-24)
- Messages API task budgets (beta `task-budgets-2026-03-13`) are advisory token ceilings (minimum 20,000) the model paces itself against; they are "distinct from Managed Agents session budgets - those are hard, dollar-denominated, platform-enforced caps" — [claude-api skill, Task Budgets section]
- Managed Agents permission policies: `always_allow` / `always_ask` / `auto` (auto runs, denies high-risk, or pauses when indeterminate) — [claude-api skill, managed-agents-tools]
- Vault credentials for Managed Agents MCP/OAuth: "Anthropic manages token refresh on your behalf"; secrets substituted at egress and never visible in the sandbox — [Managed Agents: Start a session](https://platform.claude.com/docs/en/managed-agents/sessions); [claude-api skill]

### Inferences
- Minimum robust stack (monthly, fixed): dedicated Anthropic workspace (free) + prepaid credits with auto-reload OFF (hard backstop) + workspace spend limit with email alert; Managed Agents scheduled deployments with per-run `budget` (no server to run; cost is tokens + $0.08/running hour) OR Agent SDK on Railway (~$10) / Hetzner CPX22 (~€20); Langfuse Hobby ($0) or Core ($29); n8n self-hosted ($0 on the same VPS) or Starter (€24); Temporal pay-go ($0–5 at solo volumes) only if you have multi-day workflows; Stripe (percentage only); Attio free. Fixed total ≈ £10–£60/month lean, ≈ £100–£150/month comfortable, before model spend and outbound tooling (Instantly ~$47 + Apollo ~$59 adds ~£80).
- The operator's "no metered API in automation" rule can be lifted safely with layered caps, outermost first: (1) prepaid balance, auto-reload off — the API physically stops when credits run out; (2) a non-default workspace per agent with a monthly limit well under the org limit and an email alert at ~50%; (3) for Managed Agents, a per-run `budget` on every deployment (e.g. "200" = $2 per run) so a looping run cannot exceed a known figure; (4) in code, `max_tokens`, `max_uses` on web search, task budgets, and a hard turn/iteration counter; (5) a daily cost query against the Admin usage/cost reports or Langfuse to alert on anomalies. With (1) and (3) in place the worst-case monthly loss is the prepaid balance, which the operator chooses.
- Because the legal page ties Max OAuth to "ordinary, individual usage" and requires API keys for "products or services", revenue-generating unattended agents must run on an API key. The Max plan remains valuable for the operator's own interactive Claude Code work (building and debugging the agents), which is where the heavy, unpredictable token use happens; production agents on an API key are then small, predictable, capped jobs.
- Managed Agents is the only option in this list that gives a platform-enforced dollar cap per run; everything else relies on the operator's code or a gateway (Helicone/LiteLLM) to stop spend.

## Key question 2: Managed Agents vs self-hosted orchestration for a solo operator in 2026

### Takeaway
Managed Agents removes the loop, scheduler, sandbox, secret handling and per-run spend enforcement from the operator's plate for $0.08 per running hour plus tokens, at the cost of Claude-only lock-in, beta status, no Batch discount, and Anthropic sitting in the availability path; self-hosting (Agent SDK / Tool Runner / n8n / Temporal on a ~€20 VPS) keeps portability and Batch pricing but makes the operator responsible for every reliability pattern.

### Cited Findings
- "Managed Agents is the right choice when you want Anthropic to run the agent loop and host the container where tools execute... If you want to host the compute yourself or run your own custom tool runtime, Claude API + tool use is the right choice" — [claude-api skill, Which Surface]
- Managed Agents built-in session features: automatic context compaction, prompt caching, extended thinking on by default; sessions have statuses idle/running/rescheduling/terminated; "Errors surface as session.error events"; every session has a live Console trace view — [claude-api skill, managed-agents-core]
- Managed Agents supports outcomes (a separate grader iterates the agent against a rubric until it passes), multi-agent workflows, webhooks, memory stores, vaults, GitHub integration, and self-hosted sandboxes "on your own infrastructure" — [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview), [claude-api skill]
- Batch API discount does not apply to Managed Agents; fast mode and data-residency discounts also excluded (3P adds this) — [Anthropic pricing page](https://platform.claude.com/docs/en/about-claude/pricing), [TrueFoundry](https://www.truefoundry.com/blog/claude-managed-agents-pricing)
- 3P analysis: self-hosting gives "more control and a more predictable subscription-style cost"; managed "shortens time to production and cuts operational work but brings token-variable runtime pricing"; break-even "depends on how much engineering time you currently spend on agent plumbing"; managed puts Anthropic "in your availability and compliance path" and its "SLA track record is still early" — [contextstudios.ai](https://www.contextstudios.ai/blog/claude-managed-agents-le-virage-infrastructure)
- 3P (competitor): Managed Agents is "pro-code only, with agent definitions written as JSON, and running only on Claude models"; data and execution live on Anthropic infrastructure; Hermes Agent positioned as the multi-provider self-hosted alternative — [TrueFoundry](https://www.truefoundry.com/blog/claude-managed-agents-vs-hermes-agent)
- Agent SDK = "Claude Code packaged as a library" with built-in Read/Write/Edit/Bash/Glob/Grep/WebSearch/WebFetch, MCP, subagents, hooks, permissions; "harness only - you host and deploy" — [claude-api skill]; [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)
- Scheduled deployment failure behaviour: rate-limited session creation recorded as `session_rate_limited_error` without retry; archived agent/environment/vault auto-pauses or auto-archives the deployment; "Missed triggers are not backfilled" — [Scheduled deployments](https://platform.claude.com/docs/en/managed-agents/scheduled-deployments)
- Practitioner guidance (3P): agentic systems need durable execution (checkpoints, resume after worker kill) rather than smarter prompts; Temporal-style durable workflows are cited as the pattern — [urandom.io](https://urandom.io/blog/2026-02-23-agentic-ai-needs-durable-execution-not-just-smarter-prompts)

### Inferences
- For a solo operator the decisive factor is operational surface area, not sticker price. The $0.08/hour runtime fee is small relative to tokens (Anthropic's own example: 14% of a $0.58 session), and the per-run dollar budget plus cron scheduling plus vault secrets replace three or four self-hosted components the operator would otherwise maintain and monitor.
- Choose self-hosting when: the workload is batchable (Batch halves token cost and Managed Agents cannot use it), when non-Claude models are needed (e.g. open-weight video/image models on a GPU), or when the agent must run inside the operator's own network/GPU box (e.g. the ComfyUI pipeline). A hybrid is natural: Managed Agents for scheduled research/outreach/reporting jobs; a local or rented GPU worker with its own queue for media generation.
- Beta status is a real risk for revenue-generating work: pin agent versions in sessions (`version` field) and keep an Agent SDK fallback that can run the same prompts if the beta API changes.

### Gaps
- No published Managed Agents SLA or uptime history was found.
- No independent (non-vendor) benchmark of Managed Agents vs self-hosted reliability or cost at solo scale was found.

## Key question 5: Observability and eval practices that stop silent failures and runaway spend, plus reliability patterns and reported failure modes

### Takeaway
Runaway spend comes from loops, retries and growing context where every call is individually valid, and the damage is set by detection lag, so enforcement must sit on the request path (hard dollar budgets, prepaid balance, max turns) rather than in dashboards; silent failures ("reported done, wasn't") need per-run output checks, durable side-effect records with idempotency keys, human gates on irreversible actions, and the lethal-trifecta rule (never combine private data, untrusted content and outbound communication in one agent).

### Cited Findings
- Runaway cost "is generally treated as a loop, recursive plan-execute cycle, or ever-growing context. Each individual call may be legal, schema-valid and within the context window, but the aggregate spend is pathological" — [futureagi glossary](https://futureagi.com/glossary/runaway-cost/)
- "a dashboard that notices spend after 30-120 minutes is too late"; the controlled scenario "assumes enforcement at the request path, not just alerting" (modelled, not measured) — [SatGate runaway spend benchmark](https://satgate.io/ai-agent-runaway-spend-benchmark)
- Incidents reported (3P, unverified): agent deployed five 48-vCPU AWS instances with no cost preview, $6,531 bill; LangChain multi-agent loop ran 11 days undetected, $47,000 — [contextqa](https://contextqa.com/blog/cost-of-ai-agent-failures/)
- Silent-success failure: "the agent takes a wrong action and reports success, so no alarm fires" — [Towards AI](https://pub.towardsai.net/the-ai-agent-failure-that-never-throws-an-error-e87ca9e639e5), [Amplitude](https://amplitude.com/explore/analytics/ai-agent-failure-modes)
- Mitigations recommended: per-session token budgets, per-tool caps, stop new paid calls at cap, hand off to a person when the cap is hit — [prefactor](https://prefactor.tech/problems/runaway-agent-costs), [jumpcloud](https://jumpcloud.com/?p=148508)
- Idempotency pattern: give every tool call `idempotency_key`, `correlation_id`, `attempt_number`, `deadline_ms`, `side_effect_class`; "reads can retry freely, writes only with idempotency, and destructive actions need explicit human confirmation"; "Compensation should be deterministic and testable, and asking the model what to undo is not a control strategy" — [urandom.io: idempotency, retries, compensation](https://urandom.io/blog/2026-03-03-agentic-ai-idempotency-retries-and-compensation)
- Audit logs vs transcripts: "A transcript claim like 'I already sent the email' is not a reliable state record, while a durable event recording the operation ID and its delivery status is" — [urandom.io: idempotent tools and checkpoints](https://urandom.io/blog/2026-04-14-agent-reliability-idempotent-tools-checkpoints)
- Reliability testing: inject network failures and verify no duplicate side effects; kill workers mid-run and ensure resume from checkpoint; "a 90% benchmark score can correspond to roughly 70% reliability in production" when the same task is retried across sessions — [urandom.io: SRE problem](https://urandom.io/blog/2026-03-01-agentic-ai-reliability-is-an-sre-problem), [ecorpit](https://ecorpit.com/engineering-lessons-shipping-enterprise-ai-agents-2026/)
- Secondary statistics (unverified, conflicting): "88% never reach production" attributed to Gartner; 31% of orgs have an agent in production; a March 2026 study of 6,259 production agents found a 56.6% success rate; as of Sept 2026 no standards body defines "AI agent uptime" or "human intervention rate" — [delos](https://delos.so/blog/ai-agent-reliability-enterprise-production), [intuitionlabs](https://intuitionlabs.ai/pdfs/long-running-ai-agents-reliability.pdf)
- Lethal trifecta (Simon Willison, 16 June 2025): private data + untrusted content + external communication; "the LLM vendors are not going to save us! We need to avoid the lethal trifecta combination of tools ourselves"; "In web application security 95% is very much a failing grade"; canonical example is the GitHub MCP exploit — [Simon Willison](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/), [HiddenLayer](https://www.hiddenlayer.com/research/the-lethal-trifecta-and-how-to-defend-against-it)
- Anthropic-side controls that implement these patterns: Managed Agents `always_ask` permission policy and `user.tool_confirmation` round-trip; `session.usage` events carrying cumulative `list_cost` on every idle; `session.error` events; Console session trace viewer; OpenTelemetry export; Agent SDK hooks and permissions; web tools can be disabled or restricted with `allowed_hosts`/`allowed_domains` in Managed Agents environments — [Session budgets](https://platform.claude.com/docs/en/managed-agents/budgets), [claude-api skill: managed-agents-tools, opentelemetry], [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)
- Prompt-caching hygiene matters for spend: "Verify with usage.cache_read_input_tokens - if it's zero across repeated requests, a silent invalidator is at work (datetime.now() in system prompt, unsorted JSON, varying tool set)" — [claude-api skill: Prompt Caching]
- Effort as a spend lever: "Judge cost per completed task, not per request - a cheaper request that needs more turns or retries to finish the job isn't cheaper"; use `low` effort for subagents/simple tasks — [claude-api skill: Thinking & Effort]
- Langfuse/Braintrust/LangSmith/Helicone pricing and roles: see question 1. Helicone's gateway can hard-stop at a cents cap with HTTP 429 (3P) — [innfactory](https://innfactory.ai/de/leistungen/ai-gateway/vs/helicone/)
- Observability tooling with eval support: Braintrust free tier includes 10,000 evaluation runs (vendor claim) — [Braintrust](https://www.braintrust.dev/articles/langfuse-alternatives-2026); LangSmith overage $2.50 per 1k traces (3P) — [dupple](https://dupple.com/learn/best-llm-observability-tools)

### Inferences
- Practical minimum for a solo operator:
  1. Spend: prepaid balance + workspace limit + per-run Managed Agents budget (or in-code max-iterations and `max_tokens`) + web-search `max_uses`. Alert at 50% of the monthly cap by email; check `usage.list_cost` after every run and fail the run if it exceeds 2x its historical median.
  2. Silent failures: every scheduled job must emit a structured result record (output location, item counts, checksum) to a durable store the operator reads daily; treat "no record" as failure, not success. Use Managed Agents outcomes/rubrics for single-deliverable jobs so a grader, not the agent, declares done.
  3. Side effects: every outbound action (email send, CRM write, payment, file publish) goes through a tool with an idempotency key and is logged as an event with external ID; retries only for reads and idempotent writes; destructive or customer-facing actions behind `always_ask` or a queue the operator approves each morning.
  4. Security: split agents so no single agent has all three trifecta legs — e.g. a research agent reads the web but cannot send email; an outreach agent sends email but only from operator-approved drafts and never reads untrusted inbound content.
  5. Evals: keep a 20–50 item golden set per job type in Langfuse (free tier is enough), run it before any prompt/model change, and log cache hit rate and cost per completed task as first-class metrics.
- The reported solo-operator failure modes are not well documented as first-person postmortems; the evidence is dominated by vendor blogs. The consistently cited modes are: unbounded loops/retries, polling triggers burning quota (n8n), silent success reports, duplicate side effects after retries, missed/duplicate cron firings around DST, and credential misuse (Max OAuth in scripts leading to account action).
